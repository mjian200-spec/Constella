# B版规则抽取提示词竞争性审查与修改建议

## 结论

B版的问题不是某一条原则完全错误，而是多条“默认/必须/优先”同时作用，模型在复杂句中为了满足格式约束而机械重组命题。建议保留属性绑定与证据闭合改进，降低C/R默认归位、共同条件和互斥拆分三类指令的强制性。

本文只提出建议，未修改正式提示词。

## 1. C被限定为“不参与箭头关系的外部边界”过于绝对

B版核心定义：

> C只保存不参与箭头关系、却限制整组R适用范围的外部边界；R左侧保存直接参与关系的输入。

问题：工业文档中的“场景条件、可实施条件、固定设置、适用范围”经常既能解释为触发条件，也能作为后续多条动作的共同范围。强制要求C完全“不参与关系”，会迫使模型虚构一个入口R，或把同一条件在C和R间来回移动。

`context_000400`说明原定义需要放宽：

```text
C: 焊接对象|薄板 + 工件|具备装夹条件
R: 焊接方式|利用夹具 —[要求]→ 正面|压紧
R: 焊接方式|利用夹具 —[要求]→ 背面|加上铜垫板
```

只要C随整组规则入图，这个表达已经保存了适用条件，无需再强制生成“薄板+可装夹→利用夹具”。

建议改为：

> C保存本组R共同成立的场景、适用范围或实施前提；R左侧保存当前箭头关系中发生变化、执行动作、被比较或被映射的直接参与项。C可以包含原文条件句中的内容，只要它确实共同限定本组全部R。不要为了证明C而额外生成入口规则。

## 2. “同句共同触发默认放R左侧”把句法共现误当逻辑AND

B版指令：

> 同一个明确条件句中共同触发结果的多个条件，默认共同写在R左侧。

问题：模型先识别“同句多个因素”，再套用 `+`，但没有可靠判断必要条件、备选条件、并列贡献和因果链。

实际错误：

- `000539`：`加负脉冲或保持较低峰值` 被改成 AND。
- `000449`：浓度和结合能力是否应作为联合因素，需要跟随原文“不但……而且/和”的明确证据，不能只依据同句。
- `000770`：氧化物、阴极斑点、电弧稳定、熔池流动性被机械合并或拆开。

建议删除“默认共同”规则，改成四步语义判定：

1. 原文明示“同时、共同、配合、既……又……”且缺一会改变结论时，使用 `+`。
2. 原文明示“或、任一、分别、可以A也可以B”时拆成多条R；当前阶段不输出OR语法。
3. A导致B、B导致C时保持两条因果链，不得写成 `A+B→C`。
4. 只知道多个因素与同一结果相关、但无法证明必须同时成立时，不使用 `+`；按原文分别输出，或保持上位概括而不制造充分性。

## 3. “无法判断时优先放R.input”是位置兜底，不是语义兜底

B版指令：

> 无法判断是外部边界还是关系输入时，保守写在R左侧。

问题：放入R并不会自动确定它应与哪一项组合。`000126`中B仍把15A与两个脉冲拆开，说明真正错误发生在命题划分，而不是C/R位置选择。

建议改为：

> 无法判断C/R前，先按原文标点、关系词和指代还原最小命题。若仍无法证明条件归属，不跨句合并，不把它与其他输入用 `+` 绑定；优先保留原句中的局部关系，必要时少抽而不制造新的充分条件。

## 4. “互斥取值必须拆组并复制共同R”容易造成输出膨胀

B版同时要求互斥值逐值拆组、允许重复共同R、相同R只能输出一次。三个要求在复杂包中存在张力：

- 按范围复制R会产生文本重复。
- “相同R只能一次”又诱导模型把互斥范围合并回一个C。
- 长输出增加漏项、重复和反思地址错误概率。

建议明确重复的作用域：

> 相同C内不重复R；不同互斥C下允许同文R重复。只有原文明示某R对每个互斥值均成立时才复制。若原文直接给出一个上位类别且该类别本身是稳定领域对象，使用上位类别，不自行合成“几种之一”的新实体。

## 5. “逐项列出并列因素再逐项核对”与“资源不强制抽取”竞争

B版一方面规定表格、公式、图片只是核对资源；另一方面要求先逐项列出正文并列因素、结果和参数并逐项覆盖。模型可能把“逐项覆盖”扩大到支撑表格或图像。

`000015`中两版都转写整张最低激励电压表，说明资源边界仍弱。

建议把核对对象限定为“已选中的核心命题”：

> 先从核心正文确定必须抽取的命题清单；图表公式只核对这些命题，或补充正文明确指向但缺少具体值的字段。不得因为资源中存在更多行、点或公式而扩展命题清单。

## 6. 基础提示词与专项提示词重复强调C/R，造成指令放大

B版在base、text、image、table、formula和reflector中重复“标题只是候选、共同条件进R、无法判断进R”。对简单包有帮助，但复杂多模态包会同时拼接多个专项system，等价于重复加权同一启发式。

建议：

- base只定义一次C/R与逻辑组合原则。
- text只负责句法证据与指代。
- image只负责视觉标注、方向和OCR核对。
- table只负责表头路径和单元格归属。
- formula只负责普通公式与等价变换。
- 专项提示词不再重新规定C/R默认位置。

## 7. Few-shot应提供“相似表面、不同逻辑”的对照组

现有few-shot主要告诉模型某个案例的正确输出，容易学习表面词形。例如看到“如果/在……时”就模仿 `000400`，或看到并列因素就全部使用 `+`。

建议新增四组对照示例，每组都给核心原文和输出：

1. 同句AND：`同时施加130V电压脉冲和300A电流脉冲，并在15A下……`，三项共同输入。
2. 同句OR：`加负脉冲或保持低峰值可降低飞溅`，拆成两条R。
3. 共同C：固定材料、板厚、焊速共同限定多条参数趋势。
4. 因果链：`A导致B，B导致C`，保持两条R，不写 `A+B→C`。

对照示例比重复多个同类型正例更能约束复杂逻辑。

## 8. 生成提示词承担的任务过多

B要求一次完成证据筛选、命题划分、C/R归位、AND判断、互斥拆组、实体属性化、路由专项处理和最终DSL格式。复杂包中这些任务竞争注意力。

在不增加新程序结构的最小方案下，建议让模型在内部按固定顺序检查，但只输出DSL：

1. 选出必须抽取的最小命题。
2. 为每个命题确定直接关系词和左右参与项。
3. 判断是否有共同适用范围C。
4. 最后判断同一箭头左侧是否确有AND。
5. 完成属性绑定与格式化。

关键是先确定命题，再做C/R；不能用C/R默认规则替代命题划分。

## 建议的最小修改范围

如果只做最主要修改，建议：

1. 保留裸数值必须绑定属性。
2. 保留资源出现不等于必须抽取。
3. 保留C可为空。
4. 删除“同句多个条件默认共同放R”。
5. 删除“无法判断默认放R”。
6. 放宽C定义为“共同场景、范围或实施前提”，不要求完全不参与条件语义。
7. 增加AND、OR拆R、因果链三组对照few-shot，但不引入OR/AND/XOR新语法。

这组修改能保留B在简单包上的属性和格式收益，同时减少复杂包中的机械AND和错误命题重组。
