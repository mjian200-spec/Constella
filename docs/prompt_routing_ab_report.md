# 多模态抽取路由与真实上下文包 A/B 测试报告

## 1. 结论

已实现按证据形态组合的抽取路由。同模型 A/B 中，路由版整体优于当前统一提示词：速度更快，图片尺寸绑定、表格层级恢复、公式位置和文档位置去除均有明显改善；但仍有正文漏抽、冲突表格猜测、对象自环和公式错绑，因此尚不能只凭 40/40 可解析就直接全量替换。

根据后续方案确认，生产抽取已只保留结构路由：每个包始终执行正文模块，并按实际资源叠加图片、表格和公式专项模块。统一生成提示词、baseline 分支及 `--prompt-routing` 开关已经删除。本文其余 A/B 数据保留为切换决策的历史依据。

## 2. 路由设计

每个上下文包始终命中 `text`，再根据解析后的资源类型叠加零到多个专项模块：

```text
上下文包
  └─ text（始终）
      ├─ image（存在图片）
      ├─ table（存在表格）
      └─ formula（存在公式）
```

不是在图片、表格、公式中三选一。例如同时含图片和表格的包使用 `text+image+table`，避免专项路由替换正文抽取。路由提示词 ID、模块版本均进入缓存身份，切换路由或修改任一模块不会复用旧模型结果。

专项职责如下：

| 模块 | 主要任务 | 关键保护 |
|---|---|---|
| text | 因果、要求、阈值、比较、状态变化及相邻机理链 | 临近约束必须实际统领当前事实；具体触发因素留在 R 左侧 |
| image | 尺寸线、引出线、视觉方向、OCR 字形和单位核对 | 图号和绘图样式不入图谱；图片只补充闭合事实，不替代正文 |
| table | 重建表题、分组表头、行头、列头和单元格的层级路径 | 图例缺失不解释符号；列数冲突不猜映射；独立值与参数包分开处理 |
| formula | 区分普通公式与明示等价/化简 | 普通公式放箭头中；只有明示等价且两式完整时才放等式两端 |

反思输出仍采用稀疏补丁。模型违反补丁协议时，不由解析器吞掉包装文字，而是交给独立的短协议修复提示词重写；修复调用单独计数。生成最大输出保持 8192 token，反思限制为 4096，协议修复限制为 2048。

## 3. A/B 设计

- 模型：本地 vLLM `qwen3.8-27b`，temperature=0。
- A：当前统一生成提示词。
- B：`text + 命中专项模块` 的组合生成提示词。
- 样本：40 个真实上下文包，每层 8 个，包含纯文本、图片、表格、公式和混合资源。
- 选样：固定高风险语义案例加各层复杂度高的真实包，清单由脚本确定性生成。
- 执行：4 并行，不连接 Neo4j，不修改图数据库。
- 判定：机器指标只统计解析成功、调用和延迟；规则数减少不自动视为更好，另外逐项阅读上下文、A 输出和 B 输出。

原始材料位于：

- `outputs/prompt_routing_ab/manifest.json`
- `outputs/prompt_routing_ab/final_ab_v9_qwen38_27b/comparison_metrics.json`
- `outputs/prompt_routing_ab/final_ab_v9_qwen38_27b/comparison_records.json`

## 5. 人工语义检查

### 明确改善

1. `context_000391`：A 把 `0.2~0.5mm` 和 `5~10mm` 都写成“槽隙”；B 根据图片尺寸方向分别绑定为槽深和槽宽，同时保留正文中的垫板、山形接头和气隙规则。
2. `context_000505`：A 把 `图5-30b` 当作结果对象；B 删除图号规则，保留短路小桥、电磁收缩力、爆炸飞溅和直流电感抑制的完整链条。
3. `context_000037`：B 把普通计算公式完整放在箭头中，并同时保留每种气体的电离能和临界波长；A 的公式 OCR 为 `1 2 3 6 0` 且表格行只保留结果。
4. `context_000488`：关联表格没有符号图例。B 没有像早期路由版本那样逐格生成 `◎对应◎`，转而保留正文直接说明的抗风、焊道外观和脱渣性。
5. `context_000743`：A 对大表生成大量“保护气体成分→保护气体成分”的对象/状态自式映射；B 聚焦正文及可靠分类范围，噪声显著减少。
6. `context_000786`：B 按母材、接头、板厚、焊丝构造 C，并把每个姿势的参数保持为完整参数包，没有逐参数拆爆。
7. `context_000904`：B 将普通化学反应式完整放在箭头中；`context_000908` 只保存当前包完整的式(5-28)，没有伪造缺失结果式的公式变换。
8. `context_000540`：两版均保留化简条件和两端公式，公式等价表达正确。

### 明确回归或仍未解决

1. `context_000260`：B 只保留纵向磁场控制电弧方法，漏掉正文中的 TIME 焊；A 保留两类方法。
2. `context_000386`：表格列数冲突。B 虽消除了 A 中 `37cm/min` 同时对应两个频率的冲突，并保留“低于10Hz”，但仍猜测其余速度—频率映射，违反专项提示中的“不可靠时不映射”。
3. `context_000488`：B 的高效率规则仍产生“金属型药芯焊丝|高效率→金属型药芯焊丝|高效率”自环；抑制无图例表格成功，但正文规则仍需修正。
4. `context_000786`：`5083或5052` 仍被合并为一个状态，没有拆成独立母材取值。
5. `context_000801`：两版都沿用 OCR 错误“预热前焊件正常”，没有根据图片恢复“预热器工作正常”。
6. `context_000900`：正文目标是熔池长度，但关联公式左端是温度分布。B 仍将两者错误绑定，公式专项的目标量一致性检查没有稳定生效。

这些案例说明路由提示词已经解决一部分系统性错误，但模型仍会违反明确写出的负向保护条件；40/40“可解析”不能代替人工语义审核。

## 6. 是否启用

当前实现：结构路由是唯一生产抽取路径，不再提供统一提示词回退。旧运行的提示词身份与结构路由不一致时禁止直接恢复，避免同一 run 混用两种策略。

下一步的最小有效改进是：

1. 用 `context_000260` 增加“正文并列方法不可漏掉”的正文专项回归；
2. 将冲突表格从提示词禁令升级为路由前的结构可信度标记，低可信表格不传具体错位单元格；
3. 对属性自环、单条 R 多箭头和公式目标量不一致建立审核候选；
4. 后续回归以结构路由自身的版本间对比为主，不再使用已删除的统一生成路径。
