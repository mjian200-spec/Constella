# 反思阶段问题总结与收紧方案

基于 `run_33bca2a1aa1b435a` 的40个真实上下文包。模型为本地
`qwen3.8-27b`，generator v10，reflector v14；无Neo4j交互，无旧模型输出缓存。

## 实测现象

- 40个生成初稿全部满足“规则组→C→R”，反思地址也全部能正确定位。
- 14包返回 `NO_CHANGES`，26包输出补丁。
- 26份补丁中至少4份是逐字无效替换：`context_000043`、`000392`、`000449`、`000481`。
- 多份补丁只改变措辞、关系词或状态写法，没有改变事实，也没有修复人工发现的核心错误。
- 明确有价值的补丁主要是：删除无证据公式、把裸R补成完整关系、补充直接遗漏规则、修正明确对象或数值。
- 高风险补丁主要是：新增无关C、把某条R输入提升为整组C、合并独立表格取值、整组删除后重建、保留或制造属性自环。

## 问题分类

1. **修改门槛过低**：模型把“能换一种写法”误当成“必须修改”，产生无效REPLACE_R。
2. **事实变化检查缺失**：补丁前后事实等价，仍输出多条命令，增加失败面和阅读成本。
3. **C作用域过度修正**：模型看到具体参数后倾向于加入C，但这些参数常只属于部分R。
4. **过度压缩表格**：为减少组数合并多个材料、直径或方案，违反独立取值要求。
5. **局部修正掩盖核心错误**：修正词语和格式，却遗漏OCR错误、公式缺失、方向错误和属性自环。
6. **大补丁风险过高**：DELETE_GROUP与ADD_GROUP重建会改变组顺序、合并语义并触发编号冲突。
7. **反思并不等于人工审核**：地址和DSL结构识别可靠，但不能据此推断语义判断可靠。

## 修改策略

- 将 `NO_CHANGES` 设为默认结论，补丁必须满足“证据明确、缺陷明确、修改后事实明确”。
- 禁止同义改写、排版改写、逐字相同替换和仅为压缩而合并规则组。
- SET_C必须对组内全部R成立；具体输入留在各自R中。
- ADD_R、DELETE_R、REPLACE_R分别限定为直接遗漏、明确无证据、事实级错误。
- 本地补丁器忽略与原C、R或整组逐字相同的替换。
- 保留稀疏补丁机制，但通过提示词减少模型发出补丁，而不是增加新的模型审核阶段。

## reflector v15 固定初稿复测

复用上述40包的同一份 generator v10 初稿，只重新调用 reflector v15，因而新旧结果可直接比较：

| 指标 | v14 | v15 |
|---|---:|---:|
| `NO_CHANGES` | 14/40 | 35/40 |
| 模型输出补丁 | 26/40 | 5/40 |
| 本地应用后文本实际变化 | 22/40 | 3/40 |
| 补丁应用失败 | 首次1/40，修复组号复用后0/40 | 0/40 |

v15输出补丁的5包中：

- `context_000481`、`context_000830` 是逐字替换，本地无效补丁过滤器予以忽略；
- `context_000255` 删除无证据公式，属于明确有益修改；
- `context_000272` 修正了过窄的气体约束和输入范围，但仍未覆盖图片中的具体形态；
- `context_000221` 调整对象—状态表达，事实收益有限。

结论：提高补丁证据门槛能显著降低无效和有害修改。反思阶段应定位为保守纠错器，不能替代生成提示词质量和人工语义验收。
