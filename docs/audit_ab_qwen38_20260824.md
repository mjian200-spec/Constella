# 规则反思稀疏补丁与审计 A/B

日期：2026-08-24

## 测试设置

- 模型：本地 vLLM `qwen3.8-27b`
- 样本：8个真实上下文包，无构造业务输入
- 包：`context_000004`、`000053`、`000108`、`000255`、`000472`、`000522`、`000540`、`000801`
- 覆盖：多条因果、公式条件、无规则、上下文约束、控制过程、图片/OCR、大型表格
- 并发：4
- Neo4j：关闭
- A路：初稿 + 反思稀疏补丁 + 本地确定性应用 + 解析
- B路：与A共享完全相同的初稿、补丁和候选DSL，再增加一次模型审计

| 指标 | A：无审计 | B：模型审计 |

| 相对初稿字符数 | 补丁比初稿4501少93.0% | 审计接近重新输出全文 |

审计在两个发生变化的包中，一次有益、一次造成灾难性全量删除；它还漏过了大型表格中的错误补丁。其解析通过率没有优于本地补丁候选。

## 旧记录交叉检查

40个真实Gemma压力记录中，反思稿和审计稿均为40/40可解析。审计改动23份文本，但没有改变任何一份的规则数量；主要变化是删除“后续改进”等包装文本。人工抽查发现审计仍保留了`context_000540`中的双箭头公式错误。因此“格式清洗”不应由一次昂贵模型调用承担。

## 决策

模型审计不具备稳定净收益，不作为生产必经阶段。默认使用：

1. 模型生成完整初稿；
2. 模型只输出稀疏反思补丁；
3. 本地代码严格校验补丁命令和地址并确定性应用；
4. 直接解析候选DSL；
5. 模型审计仅通过显式`--audit-mode model`用于后续实验。

为降低长规则组错改地址，反思输入现为每条R显示稳定`[组/序号]`。追加复测中，`context_000522`已从错改第14条变为正确命中第13条；两个高风险包均在无审计路径成功解析。`context_000801`暴露的“把母材条件写进对象名”问题加入真实few-shot后再次实测，模型正确输出`REPLACE_GROUP 16 + ADD_GROUP 18`，分别生成“母材材质|低碳钢”和“母材材质|不锈钢”两个C，未再污染R对象名。该表格中的“预热前焊件/预热器”OCR问题仍未被反思发现，模型审计也未发现，说明这类问题仍需加强图片专项检查，不能作为保留审计阶段的理由。
